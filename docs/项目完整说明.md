## 一、这个项目是干什么的？

先看一个真实场景：

> 张阿姨 68 岁，有高血压和轻度冠心病，每天吃氨氯地平、二甲双胍。
> 这两天感冒了，家人又给她买了感冒药和布洛芬。
> **这几样一起吃，安全吗？**——大多数家庭答不上来，只能靠猜。

**用药雷达就是替这个家庭"查安全"的工具。** 把患者的身体情况（年龄、疾病、肝肾功能、血压血糖）和正在吃 / 打算吃的药填进网页，几分钟内出一份报告，回答四个问题：

```
你关心的                              报告里对应的版块
─────────────────────────────────────────────────────────
哪两个药碰到一起会出事？        →     相互作用分析
                                     （本地规则逐对查 + AI 按药品
                                       档案推断，推断会明确标注）

有没有同一成分吃两遍、超量？    →     同成分超量警告
                                     + 重复用药提示

哪个药跟我的病犯冲？            →     禁忌警告
                                     （命中即明确"不建议使用"）

真出了问题怎么办？              →     危险信号清单："出现任一信号：
                                     停药、拨 120、带药就诊"
```

一句话定位：**"患者能看懂、医生能复核"的用药风险雷达**。

技术栈一句话版本：前端 React、后端 Spring Boot、数据库 MySQL、AI 用 DeepSeek 模型润色文字、Redis 可选。

### 它跟"直接问 AI"有什么本质区别？

直接问 AI"这些药能一起吃吗"，最大的隐患是 AI 可能一本正经地编（行话叫"幻觉"）。本系统的底线是——

> **事实全部来自本地知识库，AI 只负责把事实翻译成大白话。**

打分、风险等级、禁忌判定，全部由本地程序按规则逐条算出；AI（DeepSeek 模型）只做一件事：把"氨氯地平 × 某药 → 某风险"这样的查表结论，组织成患者读得懂的段落。**就算 AI 断网罢工，系统照样能出一份不含 AI 润色的确定性报告**（见 6.3 节"降级"）。

### 写进代码的 5 条安全红线

1. **本地查不到的药 → AI 外部检索分析（显著标注），AI 也无法确认的才硬拦截**：未收录的常见药（如新康泰克）由 AI 基于公开权威药品信息检索分析，报告顶部用醒目橙色横幅注明"AI 外部检索分析"并建议去人卫用药助手核实；生造药名或 AI 无法可靠确认的，仍直接输出"未收录，无法评估"，绝不给 AI 编结论的机会；
2. 医学事实（相互作用 / 剂量 / 禁忌 / 成分对应）只能来自本地知识库，AI 仅组织语言；外部检索内容属于"明确标注的推断"，**永不参与计分**，发现潜在严重风险时只把风险等级按保守原则上调；
3. AI 不可用时绝不硬编：有本地库内药但 AI 故障 → 明确报错"报告生成失败"（不保存无效报告）；药单全是库外药且 AI 故障 → 降级为本地确定性"未收录"拦截报告，不经过 AI；
4. 每份报告落库时记录**当时使用的知识库版本**，历史结论可追溯；
5. 审计日志**不含**患者身份与完整用药清单。

## 二、系统全景：一个"药店"的三层结构

整套系统可以想象成一家药店，分三块：

```
        你看到、点到的                       真正干活的                      存资料的
      【前端 · React】                   【后端 · Java】                【数据库 · MySQL】
 ┌─────────────────────┐         ┌─────────────────────┐         ┌─────────────────────┐
 │ 浏览器里的页面：      │  HTTP   │ "药师工作台"：        │   查/存  │ "仓库"（7 张表）：    │
 │ · 填患者信息和用药单  │ ◀─────▶ │ · 核对药名           │ ◀─────▶ │ · 账户               │
 │ · 看报告 / 打印      │         │ · 翻规则、算风险分     │         │ · 301 种药品档案      │
 │ · 历史记录 / 时间线   │         │ · 调 AI 写报告文字    │         │ · 相互作用/禁忌规则   │
 │ · 药品知识库         │         │ · 报告存档           │         │ · 分析报告 / 操作日志 │
 └─────────────────────┘         └─────────────────────┘         └─────────────────────┘
      相当于店面柜台                     相当于后厨                        相当于仓库

 另外还有两个"外聘/兼职"角色：
 · DeepSeek（AI）   = 请来的文字编辑，只负责把查表结论写成大白话
 · 人卫用药助手官网(pharmacy.pmphai.com) = 人民卫生出版社的权威药品数据库，
   系统提供跳转链接供查询完整说明书（不直接抄它的数据）
```

**几个日常词的对照**（后文遇到不再解释）：

- 前端 / 后端 —— 店面柜台 / 后厨
- API 接口 —— 柜台和后厨之间传单子的小窗口
- JWT 令牌 —— 进店后发的手环：凭手环证明"我是谁"，不用每次重复出示身份证
- Redis —— 门口的便签板，记点临时信息（谁刚登出、限流计数）；**没这块板也照常营业**
- 知识库 —— 店里的《用药安全手册》：301 种药品档案 + 46 组确定性相互作用规则
- HashRouter —— 前端页面地址都带 `#` 号（如 `/#/home`），这是正常设计不是故障

## 三、技术全景：每个部分用什么技术、怎么互相调用

> 第二章是"白话版"（把系统比作一家药店），本章是"技术真身版"：每一层用什么框架、一次点击在系统里怎么流转。看懂这一章，就能把这个项目专业地讲给别人听。

### 3.1 技术栈总表（每一层用什么）

```
用药雷达 · 技术栈
│
├── 前端（跑在浏览器里）
│   ├── React 18.3           页面框架：界面拆成组件的单页应用（SPA）
│   ├── react-router-dom 7    页面路由，HashRouter 模式（地址带 #）
│   ├── Vite 5                开发服务器 + 打包工具（改代码秒级热更新）
│   ├── 原生 fetch            网络请求（浏览器自带，没引第三方请求库）
│   ├── localStorage          存登录令牌和用户信息（浏览器本地小抽屉）
│   └── 手写 CSS              全部样式（无 UI 组件库），含打印专用样式
│
├── 后端（跑在服务器上）
│   ├── Java 17 + Spring Boot 3.3    应用骨架，自带内嵌 Web 服务器
│   ├── Spring Security             安全框架：所有接口的权限拦截
│   ├── JJWT 0.12                   JWT 令牌的签发与校验
│   ├── MyBatis-Plus 3.5            数据库读写（SQL 映射成 Java 方法）
│   ├── Lombok                      Java 减负（自动生成样板代码）
│   └── Maven                       构建打包成可执行 jar
│
├── 数据
│   ├── MySQL 8.0（必需）            7 张业务表
│   └── Redis（可选）               登出令牌黑名单 + 接口限流
│
└── 外部服务
    └── DeepSeek API（deepseek-chat 模型）报告文字润色，断网自动降级
```

**选型理由（讲解时最常被问的四个"为什么"）**：

- **为什么前后端分离？** 前端只管"长什么样"，后端只管"算什么"，两边靠 `/api` 接口用 JSON 说话。改界面不用动后端，加药品规则不用动前端。
- **为什么地址带 #（HashRouter）？** 单页应用切页其实没有真的刷新，路由全由前端管理；带 # 的地址扔到任何静态服务器都能直接打开，不需要服务器做额外配置。
- **为什么用 JWT 不用 Session？** Session 要求后端记住"谁登录了"，一重启就丢；JWT 是带签名的"手环"，后端不存任何会话，验签即认人，天然适合前后端分离。
- **为什么 Redis 是可选的？** 它只负责两件加速小事（登出黑名单、限流计数）。系统按"缺了也能跑"设计：Redis 不在，功能一个不少，这两件小事暂时从简处理。想要完整体验时，双击启动脚本会主动询问是否一键安装便携版 Redis（装在项目 runtime\ 内，删项目即清除），或手动运行 `scripts\setup-redis.ps1`。

### 3.3 网页各部分用的什么技术（逐个说）

**按页面**：

- **欢迎页** —— 静态介绍 + 统计徽章，进页面时调 `GET /api/medications/stats` 拿"收录 301 种药"这类实时数字
- **登录 / 注册页** —— React 受控表单；提交 `POST /api/auth/login`，后端校验通过后签发 JWT，前端存进 localStorage
- **用药分析页（最重的表单）** —— 药名联想输入（技术拆解见下）、患者情况与用药清单的受控组件，提交 `POST /api/analyze` 后跳转报告页
- **历史报告 / 分析记录页** —— `GET /api/reports` 分页拉取；医生端在前端按"患者标识"分组展示
- **报告详情页** —— 同一份数据按登录角色渲染患者版 / 医生版；右上角打印按钮（技术拆解见下）
- **健康时间线** —— 纯 React + CSS 手绘，把同一人历次报告的风险分连成趋势（没有引入图表库）
- **知识库页** —— 数字分页组件（页码 / 跳页）、管理员的增删改表单；医生只读（"停用"按钮对医生直接不渲染）

**三个关键交互的技术拆解**（向别人讲解时最好用）：

药名联想搜索：

```
输入"阿司匹"
  │  防抖 300ms（停手才发请求，敲字途中不浪费请求）
  ▼
GET /api/medications/search?q=阿司匹
  │  后端按 药名 / 别名 / 分类 匹配，只返回前 10 条
  ▼
下拉列表出现；↑↓ 键选择、Enter 上屏、Esc 关闭
```

JWT 登录态（"手环"的完整生命周期）：

```
登录成功
  ▼ 后端用 JJWT 签发令牌（记录用户 id + 角色，HMAC 签名防伪造）
  ▼ 前端存 localStorage
  ▼ 此后每个请求 api() 自动加 Authorization: Bearer <令牌>
  ▼ 后端过滤链验签 → 认出"你是谁、什么角色"
  ▼ 登出：令牌进 Redis 黑名单（可选）+ 前端清 localStorage
```

打印 / 存 PDF：

```
点击"打印报告"
  ▼ window.print()（浏览器原生能力，不是自研导出器）
  ▼ @media print 样式接管：隐藏导航 / 按钮 / 外链，只留报告内容
  ▼ 分页规则：每张卡片 break-inside: avoid，整块不跨页
```

### 3.4 API 接口清单（后端提供的全部"柜台窗口"）

**认证 `/api/auth`**

- `POST /register` —— 注册（选 patient / doctor），公开
- `POST /login` —— 登录，返回手环和用户信息，公开
- `POST /logout` —— 登出，手环进撤销名单，需登录
- `GET /me` —— 当前用户，需登录

**分析 `/api/analyze`**

- `POST /api/analyze` —— 用药分析（游客不保存），公开，限流 6 次/分/IP

**报告 `/api/reports`**

- `GET /api/reports` —— 自己的报告分页列表，需登录
- `GET /{id}` —— 报告详情（仅本人），需登录
- `POST /{id}/favorite` —— 收藏，需登录
- `DELETE /{id}` —— 删除自己的报告，需登录

**药品 `/api/medications`**

- `GET /search` —— 药品搜索联想，公开
- `GET /page` —— 药品分页列表，公开
- `GET /stats` —— 分类统计，公开
- `GET /interactions` —— 相互作用规则，公开
- `GET /{id}` —— 药品详情，公开
- `POST / PUT /{id} / PATCH /{id}/disable / DELETE /{id}` —— 新增 / 修改 / 停用（需填原因）/ 物理删除，**仅 ADMIN**，全量审计

**其他**

- `GET /api/stats` —— 统计，需登录
- `GET /api/health`、`/api/health/ready` —— 健康检查，公开（启动脚本靠它判断就绪）

### 3.5 改了代码之后怎么让它生效

- **后端**：先停掉占用 8080 的 java 进程（jar 被锁改不了），在 `backend-java/` 执行 `mvn clean package -DskipTests`，再重启
- **前端**：`npm run dev` 模式下改代码即时热更新；`npm run build` 产出 `frontend/dist/` 静态文件
- **数据库**：表结构变更写新的编号 SQL 脚本，按序执行（沿用 01→07 的惯例，历史脚本永不改写）

## 四、三种角色，各自能干什么

系统有三类登录角色，权限刻意不一样（为了隐私与职责分离）：

```
        ┌─────────────┬─────────────┬─────────────┐
        │    患 者     │    医 生     │   管理员     │
        └──────┬──────┴──────┬──────┴──────┬──────┘
               │             │             │
        发起用药分析    发起用药分析    维护药品知识库
        看自己的        给不同患者      （新增/修改/停用/
        历史报告        建分析记录      删除药品，全量留痕）
        健康时间线      只读知识库
               │             │             │
               ▼             ▼             ▼
        报告 = 患者版   报告 = 医生版   不能发起分析、
        通俗结论+行动   决策式表述+     不能查看任何
        指引+饮食建议   评分明细        患者报告
```

**权限矩阵**（✅ 可以 · ❌ 不可以）：

```
                          患者         医生         管理员
发起用药分析              ✅           ✅           ❌
（游客也可以，报告不保存）
查看历史报告              ✅ 自己的     ✅ 自己发起   ❌
（患者端叫"历史报告"，
 医生端叫"分析记录"，
 按患者标识分组）
健康时间线                ✅           ❌ 已移除     ❌
浏览药品知识库            ❌           ✅ 只读      ✅ 可维护
登录后落在               用药分析     用药分析      知识库管理
```

**为什么医生没有时间线？** 医生的分析记录来自不同患者，混在一条时间线里没有统计意义；医生找报告用"分析记录"的按患者分组即可。

**为什么管理员看不到报告？** 管理员只管知识库，不看患者数据——这是隐私边界。

### 权限是"两层锁"，缺一不可

```
 第 1 层：前端路由守卫（App.jsx）          第 2 层：后端接口拦截（SecurityConfig.java）
 像店里的引导牌：                          像仓库的铁门：
 管理员访问 /home → 自动送去 /knowledge     医生调"停用药品"接口 → 403 需要管理员权限
```

## 六、一次用药分析的完整流程（全文最重要）

这是整个系统的核心流程。跟着张阿姨的单子走一遍：

```
【你在网页上填的单子】
  患者情况：68 岁 / 女 / 高血压+冠心病 / 肝肾功能正常 / 血压血糖
  用药清单：长期药（氨氯地平、二甲双胍）+ 新加药（感冒药、布洛芬）
                     │
                     ▼
┌─ ① 核对药名 ─────────────────────────────────────────────────
│  像药师接过处方先核对药名：每个药名拿去本地药品库（301 种）查。
│   · "氨氯地平片"也能对上"氨氯地平"（自动剥掉剂型后缀再精确匹配）
│   · 部分药查不到 → 交给 AI"外部检索"：基于公开权威药品信息分析，
│     全程显著标注（横幅 + "AI检索推断"标签），永不参与计分
│   · AI 也无法可靠确认（如生造药名）→ ★硬拦截：直接出
│     "未收录，无法评估"报告，不分析、不打分——最重要的安全闸门
└───────────────────────────────────────────────────────────────
                     │
                     ▼
┌─ ② 本地规则评估（确定性引擎）─────────────────────────────────
│  像药师翻《用药安全手册》逐条查表：
│   · 禁忌：药 × 患者疾病，命中"重度"即拦截级警告
│   · 相互作用：清单里的药两两配对查本地规则库（46 组）
│   · 同成分超量：同种成分的日剂量加起来，对不对得上限
│   · 重复用药：同类药开了两遍的提示
│  这一步全部是查表逻辑，不联网、不猜，同样输入必得同样结论。
└───────────────────────────────────────────────────────────────
                     │
                     ▼
┌─ ③ 请 AI 当"文字编辑"（不是请它当医生）───────────────────────
│  把②查到的【事实】连同患者情况交给 DeepSeek，让它写成患者能读的
│  段落：机制、后果、"对您身体的影响"、饮食注意、"我该怎么办"。
│  提示词里锚定了事实，防止 AI 自由发挥。
└───────────────────────────────────────────────────────────────
                     │
                     ▼
┌─ ④ 复核与覆盖（程序说了算，AI 说了不算）──────────────────────
│   · 风险分、风险等级：只认本地计算结果，直接覆盖 AI 给的数字
│     （风险分 = 各风险项分值累加；禁忌命中时等级下限抬到"高"）
│   · 命中重度禁忌 → 结论强制改为：
│     "对您属于禁忌范围，不建议使用，请咨询医生更换其他药物"
│   · AI 对未确认药物的任何输出 → 一律剔除，不进报告
│   · 外部检索药物的分析 → 强制标注"推断"属性；推断出严重风险
│     时，风险等级保守上调到"中"（分数不变，明说保守原则）
└───────────────────────────────────────────────────────────────
                     │
                     ▼
┌─ ⑤ 出报告、存档 ──────────────────────────────────────────────
│   · 登录用户 → 报告存进数据库，可在"历史报告/分析记录"翻看
│   · 游客     → 只出报告不保存
│   · 页面按"当前登录角色"渲染成患者版或医生版（见 6.2）
│   · 右上角"打印报告 / 存为 PDF"：一键打印或存 PDF 带给医生
└───────────────────────────────────────────────────────────────
```

### 6.1 风险分是怎么算的（报告里也有这段说明）

> **风险分只统计本地知识库中已确认的用药风险**——药物相互作用、禁忌、同成分超量——按各项分值累加：**0–30 低风险 · 31–60 中风险 · 61–85 高风险 · 86–100 极高风险**。

三类计分项都是程序查本地知识库算出来的，AI 给的数字一律被覆盖：

- 相互作用（本地规则库，46 组）—— 按知识库严重程度计分：严重 20 分 / 中等 12 分 / 轻微 6 分 / 需关注 3 分。AI 推断的相互作用**不计分**（无法确定性复核），只展示并标注"推断"
- 禁忌命中 —— 按禁忌规则表里的分值（如 40 分），命中重度时等级下限抬到"高"
- 同成分超量 —— 每条 20 分（超的是每日安全上限，属于高优先级风险）

**重复用药提示不参与计分**（它由 AI 锚定生成、程序无法确定性复核），只作提示展示。

评分不包含未收录的药物和未填写的信息。**低分或 0 分只说明"未发现已知规则风险"，不等于绝对安全**——所以当低风险报告里仍有需要注意的内容时，风险徽章和仪表盘会额外标注"（有需关注项）"，提醒患者别只看绿色就放心。

### 6.2 一角色一版本的报告渲染

同一份报告数据，患者和医生看到的是**两个不同版本**（没有"切换视角"按钮，打印输出也和登录角色一致）：

```
                     ┌─ 同一份报告数据 ─┐
              ┌──────┴──────┐          │
              ▼             ▼
          患者版          医生版
     ┌─────────────┐  ┌──────────────────┐
     │ 通俗化结论   │  │ 决策式行动徽章     │
     │ 给患者和家属 │  │ （"信息不足，建议  │
     │ 的说明       │  │  核实关键指标后    │
     │ 饮食与生活   │  │  决策"）          │
     │ 建议         │  │ 评分明细表         │
     │ 危险信号+    │  │ 专业版分析         │
     │ 停药拨120    │  │ 证据级别/剂量调整/ │
     │ "我该怎么办" │  │ 替代方案           │
     └─────────────┘  └──────────────────┘
```

医生版还会自动"清洗"文案：像"建议先问医生或药师"这种对患者说的话，在医生版里会替换成决策式表述（因为医生自己就是要做决策的人）。患者向区块（饮食建议、危险信号等）在医生版整块隐藏。

### 6.3 AI 不可用时怎么办（降级与拦截）

```
 调用 DeepSeek ──► 超时/断网/限流？
                      │是              │否
                      ▼                ▼
        ┌─ 看药单里有没有本地库内的药 ─┐   正常的 AI 润色报告
        │                              │
   有库内药                      全部是库外药
        │                              │
        ▼                              ▼
  明确报错"报告生成失败"      降级为本地确定性拦截报告：
  （502，不保存无效报告）      "未收录，无法评估"，不经过 AI
```

也就是说：**AI 挂掉不会让系统"沉默地给错答案"**——要么明确告诉你"生成失败，请稍后再试"，要么对全是库外药的单子直接走本地硬拦截，绝不让 AI 缺席时硬编结论。

```

│ 第 3 份分析报告            [低风险 · 12分(有需关注项)] │

│ │ 关注项│    0 分 ≠ 绝对安全……                 │
│ └──────┘                                     │
│ ⚠ 同成分超量警告（若有）                        │
│ ⚡ AI 外部检索分析横幅（若有：列出检索的药、    │
│   提醒核实、人卫链接——橙色醒目）                │
│ ⚠ 暂无法评估药物提醒 + 人卫核实链接（若有）      │
│ 🚫 禁忌警告：不建议使用（若有，置顶强调）           │
│ 相互作用分析：一药对一卡                         │
│   机制 → 后果 → 一般人常见反应 → 对您的影响       │

│   （涉及外部检索药的对子会加"AI检索推断"小标签）  │
│ 重复用药提示（若有）                            │
│ 结合您身体情况的提示（患者版标题；医生版标题为    │
│ "患者情况对用药决策的影响"，内容换成一句话决策   │
│ 参考，不再是"您的血压…告知医生"这类患者口吻）    │
│ 饮食与生活建议 · 建议沟通点（患者版）              │
│ 危险信号：出现任一情况 → 停药、拨 120、带药就诊    │
└──────────────────────────────────────────────┘
```

**打印 / 存 PDF 的效果**：打印时自动隐藏导航栏、按钮和外链，只保留报告内容；每个版块（如一张相互作用卡片）**整块放在同一页**，不会从中间切成两半；四周留出页边距。

**"第 N 份"是什么意思**：编号按**当前账号**的第几次分析排（你的第 1 份、第 2 份……），不是全系统数据库的流水号——所以你的第一份报告显示"第 1 份"，哪怕它可能是全站的第 28 条记录。

## 七、数据库里存了什么

数据库 `medication_radar` 里有 7 张表，每张表是一排货架：

**users —— 账户**
存用户名、密码哈希（BCrypt，原文不落库）、角色。

**medications —— 药品档案**
301 种药的"身份证"：名称、别名、类别、成分、适应症、用法用量、版本号。`status` 字段标记停用（**软删除**——历史报告引用的药不能真删）。

**interactions —— 相互作用规则**
46 组"哪个药 × 哪个药"的确定性记录：严重程度、机制、后果、建议。规则库外的组合由 AI 按药品档案推断，报告中标注"推断"且不计分；库外药由 AI 外部检索分析（同样标注、不计分）。

**medication_contraindications —— 禁忌规则**
药 × 疾病关键词 + 严重程度条件。**机制已建好、当前为空表（预期状态）**，录入数据即生效。

**reports —— 分析报告**
每份报告的完整存档：风险等级、分数、患者信息 JSON（含医生填的"患者标识"）、报告全文 JSON。

**login_logs —— 登录日志**
谁、何时、哪个 IP、成功 / 失败。**不存密码**。

**admin_operation_logs —— 管理员操作日志**
知识库每次改动的前后快照。**不含患者隐私**。

> **为什么禁忌规则表是空的？** 机制已就绪（严重程度条件、评分、降级"需关注"），但本地暂无权威结构化数据可灌。在库药物照常评估，报告会提示"该药的结构化禁忌规则暂未收录本地规则库，禁忌评分维度未覆盖（其他维度照常评估）"。
>
> **医生填的"患者标识"存哪？** 存在 `reports` 表的 patient JSON 里（不建新列），历史页按它分组。输入框会警告：不要填真实姓名 / 身份证号。

## 九、部署与启动

### 先决条件

- JDK 17 —— 跑后端
- MySQL 8.0 —— 数据仓库，需要一个能建库的账号
- Node.js 18+ —— 跑前端页面
- Maven 3.9 —— 打包后端
- Redis —— 可选的加速便签板，**不装也能跑**，日志会 WARN 然后自动降级

### 首次部署（三步）

1. **建库**：按编号顺序执行 `database/sql/` 下的脚本（01 会自动创建 `medication_radar` 库和全部表 → 02 灌入 283 种药品知识 → 03~06 按需 → 07 补录 18 种日常常用药品；最终 301 种药 / 46 组相互作用规则）；
2. **配置**：把 `backend-java/.env.example` 复制为 `backend-java/.env`，填入你的 MySQL 密码、JWT 密钥（至少 32 字节随机串）和 DeepSeek API Key；
3. **启动**：Windows 双击项目根目录 `用药雷达.bat`（自动拉起后端 + 前端并等就绪）；其他平台手动执行——`backend-java/` 下先 `mvn clean package -DskipTests` 再 `java -jar target/medication-radar-backend-2.0.0-SNAPSHOT.jar`，`frontend/` 下先 `npm install` 再 `npm run dev`。

启动后打开浏览器：前端 `http://localhost:5173`；后端接口在 `http://localhost:8080`。

### 环境变量（写在 backend-java/.env 里）

- `DB_URL / DB_USERNAME / DB_PASSWORD` —— MySQL 连接
- `REDIS_HOST / PORT / PASSWORD` —— 令牌撤销、限流（可选）
- `JWT_SECRET` —— 手环签名密钥（**至少 32 字节随机串，上生产必换**）
- `DEEPSEEK_API_KEY / BASE_URL / MODEL` —— AI 文字编辑的接入凭证
- `PORT` —— 后端端口（默认 8080）
- `CORS_ALLOWED_ORIGINS` —— 跨域白名单（默认放行本地 5173）

**密钥安全提醒**：`.env` 已在 `.gitignore` 中，不会被提交；切勿把真实密钥写进任何会被提交的文件。

### 账号

- **患者和医生账号**：登录页"注册"创建（注册时选身份）
- **管理员账号**：系统不预置。先注册一个普通账号，再用数据库把它提升为管理员：

```sql
UPDATE users SET role = 'admin' WHERE username = '你的用户名';
```

- **游客**：不登录也能直接做分析，只是报告不保存

## 十、和人卫用药助手的关系

系统里所有"去查证"的入口，都是**原生链接跳转**到人卫用药助手官网（`https://pharmacy.pmphai.com/`，人民卫生出版社出品的权威药品数据库），由用户在官网自行搜索药名、查看完整药品说明书（成分、适应症、用法用量、不良反应、禁忌等全项）。此前使用药监局（NMPA）官网链接，因 NMPA 官网只能查批准文号、厂家、规格，查不到说明书全文，已于 2026-09-12 全部替换。

入口位置一览：

- 导航栏"人卫用药助手查药 ↗"（所有角色）→ 人卫用药助手官网首页
- 报告里的"未收录药物"警告块（核实药名）→ 人卫用药助手官网首页
- 报告里的禁忌警告块（查该药详情）→ 人卫用药助手官网首页
- 知识库弹窗 / 工具栏"人卫用药助手查此药 ↗"→ 人卫用药助手官网首页
- 相互作用明细"人卫用药助手查看 XX 说明书 ↗"→ 人卫用药助手官网首页

另外，本地知识库新增的日常常用药品（07 脚本），其档案栏目按人卫用药助手的说明书结构组织（成分 / 性状 / 规格 / 适应症 / 用法用量 / 不良反应 / 禁忌 / 注意事项 / 特殊人群用药 / 药理 / 相互作用提示），内容依据国家药监局批准的药品说明书编写。

## 十一、常见问题（FAQ）

**问：日志刷 `Redis unavailable...`**
答：没装 Redis。系统自动降级照常运行；想消警告可运行 `scripts\setup-redis.ps1 -Start` 一键安装并启动项目内便携版（仅本项目可用，删除项目文件夹即清除）。

**问：地址栏输入 `localhost:5173/home` 显示的是欢迎页**
答：正常。地址必须带 `#`：`/#/home`（HashRouter 设计如此）。

**问：点人卫用药助手链接没有自动带出药名**
答：官网限制，需在官网搜索框手动输入药名。

**问：搜"阿"等字眼出现不相干药品**
答：已修复：搜索优先匹配药名 / 别名 / 分类，全部无命中时才退回按适应症检索。

**问：医生在知识库看不到"停用"按钮**
答：设计如此：医生只读，维护是管理员职责（后端同样拦截 403）。

**问：医生版报告没有饮食建议 / 危险信号，也没有视角切换**
答：设计如此：一角色一版本（2026-09-12 定稿），打印输出与登录角色一致。

**问：医生端没有"分析趋势"入口**
答：设计如此：不同患者的报告混在一条时间线无统计意义，已移除。

**问：输入"氨氯地平片"提示未收录**
答：已修复：药名解析自动剥剂型后缀；若仍提示，说明该药确实不在 301 种库内。

**问：输入常见药（如"新康泰克"）不再说"无法评估"**
答：2026-09-12 起新机制：库外常见药由 AI 外部检索分析（报告顶部橙色横幅显著标注 + 每对相互作用加"AI检索推断"标签 + 建议人卫核实）；生造药名或 AI 无法确认的仍硬拦截"未收录"。

**问：医生版"结合患者情况的提示"内容像对患者说话**
答：已修复（2026-09-12）：医生版该版块改名"患者情况对用药决策的影响"，每条显示一句话决策参考（doctorNote），不再出现"您的血压…告知医生"这类口吻。

**问：报告说"结构化禁忌规则暂未收录"**
答：禁忌规则表当前为空（预期状态），其他维度照常评估。

**问：报告编号是"第 N 份"**
答：按当前账号的第几次分析编号，不是全系统流水号。

**问：低风险为什么还标"有需关注项"**
答：分数只统计已确认规则；有需关注内容但分数低时，特意提醒别只看绿色。

**问：管理员登录后没有"用药分析"**
答：设计如此：管理员不能发起分析，登录直落知识库管理。

**问：用 PowerShell 测接口中文乱码**
答：PowerShell 5 解码问题；改用 `curl.exe --data-binary @文件 -o 输出`。
