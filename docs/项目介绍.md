# 用药雷达项目介绍

> 文档状态：2026-09-13。本文描述当前正式源码，不描述旧 Node 实现。完整细节见同目录《项目完整说明.md》与《代码技术架构.md》。

## 1. 项目定位

用药雷达是面向多重用药患者及家属（以及为患者做用药复核的医生）的 Web 用药安全分析系统。用户录入患者概况、生命体征和药物清单后，系统结合本地药物知识库与 DeepSeek，生成结构化风险报告。

系统只提供用药安全参考，不作疾病诊断，不开具处方，不能替代医生或药师。

系统有三类角色：

- **患者**：发起分析、查看自己的历史报告、健康时间线；
- **医生**：为不同患者建立分析记录（按患者标识分组）、只读浏览药品知识库，报告以医生视角（决策式表述）呈现；
- **管理员**：维护药品知识库（增改停删，全量审计），不能发起分析，不能查看患者报告。

## 2. 主要功能

| 功能 | 说明 |
| --- | --- |
| 游客分析 | 未登录用户可以生成报告，但不会保存历史。 |
| 账户认证 | 注册（自选患者/医生）、登录、退出；密码使用 BCrypt，令牌使用 Java JJWT。 |
| 用药分析 | 单次支持 1-15 种药物，分"长期用药"和"新增用药"两组，结合患者情况（含治疗方案、INR、血钾等临床字段）、知识库和已知相互作用生成报告。 |
| 未收录药 AI 外部检索 | 知识库没有的常见药由 AI 基于公开权威药品信息分析，报告顶部橙色横幅显著标注并建议前往人卫用药助手核实；生造药名或 AI 无法确认的仍硬拦截"未收录，无法评估"。 |
| 角色化报告 | 同一份数据，患者看通俗版（饮食建议、危险信号、行动指引），医生看决策版（doctorNote、评分明细）；打印输出与登录角色一致。 |
| 报告管理 | 登录用户只能查看、收藏和删除自己的报告；编号按当前账号"第 N 份"。 |
| 数据看板 | 患者个人报告数量、风险分布、常用药物和近 30 天趋势（医生端无看板，不同患者混一条时间线无统计意义）。 |
| 药物知识库 | 支持名称、别名、分类和适应症检索（适应症仅在无命中时兜底）；管理员维护，医生只读。 |
| 安全审计 | 记录登录结果和管理员知识库操作，不保存密码、Token、患者资料或完整报告。 |

## 3. 技术架构

| 层级 | 当前实现 |
| --- | --- |
| 前端 | React 18、React Router（HashRouter）、Vite、原生 fetch、手写 CSS（无 UI 框架、无图表库） |
| 后端 | Java 17、Spring Boot 3.3.5、Spring Security |
| 数据访问 | MyBatis-Plus；复杂 JSON 查询和统计使用 Mapper XML |
| 数据库 | 一个 MySQL 8.0 数据库：`medication_radar` |
| 缓存 | Redis（可选）：知识库缓存、共享限流、JWT 注销状态 |
| AI | DeepSeek Chat Completions API，要求返回结构化 JSON |
| 认证 | BCrypt 密码哈希、JJWT HS256、无状态 Spring Security |

```text
React / Vite :5173
        |
        | /api
        v
Spring Boot :8080
  |       |       |
  |       |       +-- DeepSeek API
  |       +---------- Redis
  +------------------ MySQL medication_radar
```

Redis 不是业务数据库。清空 Redis 不会丢失用户、报告或药物资料；MySQL 是唯一业务数据源。Redis 不可用时系统自动降级照常运行。

## 4. 数据库

系统使用七张表：

| 表 | 用途 |
| --- | --- |
| `users` | 用户、BCrypt 密码哈希和角色（patient/doctor/admin） |
| `reports` | 患者输入（含医生端患者标识）、药单、完整报告、风险等级和收藏状态 |
| `medications` | 药物知识档案（软删除，历史报告引用的药不物理删除） |
| `interactions` | 已知药物相互作用 |
| `medication_contraindications` | 禁忌规则（机制已建、当前为空表，录入即生效） |
| `login_logs` | 登录安全日志 |
| `admin_operation_logs` | 管理员操作审计 |

数据库由开发或部署人员手工执行 SQL 初始化（`database/sql/` 按编号 01→07 顺序执行：建表 → 初始知识库 283 种药物/18 条规则 → 角色迁移 → 知识库版本治理 → 禁忌规则表 → 登录日志 → 补录 18 种日常常用药品）。当前实数：**301 种活跃药物、46 条相互作用规则**。

Spring Boot 的 SQL 自动初始化已关闭，不会在服务启动时建库、建表或修改结构。

## 5. API

| 路径 | 访问权限 | 作用 |
| --- | --- | --- |
| `GET /api/health` | 公开 | 进程存活检查 |
| `GET /api/health/ready` | 公开 | MySQL、Redis 就绪检查 |
| `POST /api/auth/register` | 公开 | 注册（选 patient 或 doctor） |
| `POST /api/auth/login` | 公开 | 登录并签发 Java JWT |
| `POST /api/auth/logout` | 登录 | 注销当前 JWT |
| `GET /api/auth/me` | 登录 | 当前用户 |
| `POST /api/analyze` | 公开/可选登录 | 分析（限流 6 次/分/IP）；管理员 403；登录用户保存报告 |
| `/api/reports/**` | 登录 | 个人报告查询、收藏和删除 |
| `GET /api/stats` | 登录 | 个人数据统计 |
| `GET /api/medications/**` | 公开 | 药物检索、详情和相互作用 |
| `POST/PUT/PATCH/DELETE /api/medications/**` | 管理员 | 药物知识维护（PATCH 为填原因停用） |

错误响应保持为 `{ "error": "错误信息" }`，便于 React 页面直接展示。

## 7. 配置与运行

Java 配置通过环境变量提供，示例位于 `backend-java/.env.example`。主要配置包括 MySQL、Redis、JWT 密钥和 DeepSeek 密钥。真实密码与密钥不得提交到仓库。

一键启动脚本会读取 `backend-java/.env`、按需构建并启动 Java 8080 和 React 5173，通过 `/api/health/ready` 等待服务就绪后自动打开浏览器。

## 8. 数据与隐私边界

- 报告包含疾病、用药和生命体征等敏感健康信息，只允许所属用户访问。
- 分析数据会发送给配置的 DeepSeek 服务，正式使用前必须明确用户授权、数据保留和脱敏规则。
- 医学事实（相互作用、剂量、禁忌、成分）只能来自本地知识库，AI 仅组织语言；AI 外部检索内容显著标注"推断"、永不计入风险分，报告内提供人卫用药助手（pharmacy.pmphai.com）核实链接。
- 当前药物资料来自历史生成和整理数据，已备份，但不等于经过临床权威审核。
- 管理员操作日志只写操作类型、目标和简短摘要，不写完整药物修改内容或患者信息。
