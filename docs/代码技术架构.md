# 用药雷达代码技术架构

> 文档版本：2.0
> 更新时间：2026-09-13
> 面向读者：开发者。通俗版全貌见同目录《项目完整说明.md》。

## 1. 架构结论

用药雷达是一个前后端分离的模块化单体 Web 应用：

- 前端使用 React 18 + Vite，负责页面、表单交互、报告展示和浏览器端会话状态。
- 后端使用 Java 17 + Spring Boot 3.3.5，负责认证、权限、业务编排、数据访问和 DeepSeek 调用。
- MySQL 8.0 是唯一业务数据库，数据库名为 `medication_radar`。
- Redis 不是业务数据库，仅保存缓存、限流计数和 JWT 注销黑名单等可重建状态。
- 不拆分微服务，不使用 Flyway，不使用启动时自动建库建表。
- 系统有三类角色：`patient`（患者）、`doctor`（医生）、`admin`（管理员）；管理员不能发起分析，医生不能维护知识库。

```text
Browser
  React + Vite :5173
       |
       | /api proxy
       v
Spring Boot :8080
  |          |          |
  |          |          +-- DeepSeek Chat API
  |          +------------- Redis
  +------------------------ MySQL medication_radar
```

## 3. 后端分层

### 3.1 Controller 层

Controller 只负责 HTTP 边界、参数接收、认证主体获取和状态码：

| Controller | 路由 | 责任 |
| --- | --- | --- |
| `HealthController` | `/api/health`、`/api/health/ready` | 存活和 MySQL/Redis 就绪检查 |
| `AuthController` | `/api/auth/**` | 注册（选 patient/doctor）、登录、当前用户、退出 |
| `AnalysisController` | `POST /api/analyze` | 校验药单、限流、管理员拦截、调用分析服务、按登录状态保存报告 |
| `MedicationController` | `/api/medications/**` | 检索、分页、详情、管理员 CRUD 与停用 |
| `ReportController` | `/api/reports/**` | 当前用户报告列表、详情、收藏、删除 |
| `StatsController` | `/api/stats` | 当前用户报告统计 |

异常由 `GlobalExceptionHandler` 统一转换为前端兼容格式：

```json
{ "error": "错误信息" }
```

### 3.2 Service 层

- `MedicationService`：药物检索（名称/别名/分类优先，适应症兜底）、剂型后缀剥离匹配、分页、分类统计、缓存和管理员写操作。
- `ReportService`：报告保存、当前用户所有权过滤、JSON 反序列化、收藏和个人统计。
- `AnalysisService`：核心分析引擎。规范化输入药物、匹配知识库、禁忌/相互作用/同成分超量评估、确定性评分（覆盖 LLM 数值）、调用 DeepSeek、AI 外部检索药物的落定与标注（推断属性强制打标、不计分）、角色化报告后处理。
- `IngredientOverdoseChecker`：按成分每日剂量上限做同成分超量检测（阈值集中在常量文件并注明出处）。
- `DeepSeekService`：封装 Chat Completions 请求、JSON 响应解析、Markdown 围栏清理和异常转换。
- `PasswordService`：只使用 Spring Security BCrypt。
- `RateLimitService`：使用 Redis 进行认证和分析接口限流。
- `TokenRevocationService`：使用 Redis 按 JWT `jti` 保存注销状态。
- `AdminAuditService`：写入管理员操作摘要和客户端 IP，不保存敏感业务正文。

### 3.3 Mapper 层

普通实体继承 MyBatis-Plus `BaseMapper`，用于 CRUD、条件查询和分页：

- `UserMapper`
- `MedicationMapper`
- `InteractionMapper`
- `MedicationContraindicationMapper`
- `ReportMapper`
- `LoginLogMapper`
- `AdminOperationLogMapper`

报告列表中的 MySQL JSON 搜索、风险聚合、JSON_TABLE 常用药统计和趋势查询放在 `ReportMapper.xml`，避免拼接 SQL。

## 4. 认证与权限

### 4.1 注册和密码

1. 用户名限制为 2-20 位中文、字母、数字或下划线。
2. 密码长度至少 6 位。
3. 注册时自选角色：`patient` 或 `doctor`（服务端校验，其他值返回 400）。
4. BCrypt 哈希写入 `users.password_hash`。
5. 不创建默认管理员，不把第一个注册用户自动设为管理员。

管理员由数据库管理员明确授权：

```sql
UPDATE medication_radar.users SET role = 'admin' WHERE username = '实际用户名';
```

### 4.2 JWT

`JwtService` 使用 JJWT 以 HS256 签发无状态令牌，包含：

- `sub`：用户 ID，字符串形式；
- `username`：用户名；
- `role`：`patient`、`doctor` 或 `admin`；
- `jti`：随机唯一令牌 ID；
- `iat`、`exp`：签发和过期时间。

密钥只从环境变量 `JWT_SECRET` 读取，长度不足 32 字节时应用启动失败。旧 Node JWT 不兼容，旧令牌会失效。

`JwtAuthenticationFilter` 校验 Bearer Token 后写入 Spring Security 上下文；`TokenRevocationService` 将退出登录的 `jti` 写入 Redis，TTL 等于 Token 剩余有效期。

### 4.3 权限矩阵（后端为最终边界）

- `POST /api/analyze`：公开（限流 6 次/分/IP）；**管理员登录态调用返回 403**（医生和患者可发起，游客可发起但不保存）。
- `GET /api/medications/**`：公开（医生、管理员、患者均可浏览知识库）。
- `POST/PUT/PATCH/DELETE /api/medications/**`：仅管理员；医生只读。
- `/api/reports/**`、`/api/stats`：登录且仅本人数据。

前端 `App.jsx` 同步做路由守卫（管理员访问分析页自动重定向到知识库、时间线仅患者、知识库医生+管理员），但拦截以后端为准。

## 5. 数据库架构

项目只使用一个 MySQL 数据库：`medication_radar`，共 7 张表：

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `users` | 用户和角色 | `username`、`password_hash`、`role`（patient/doctor/admin） |
| `reports` | 分析历史 | `user_id`、`patient` JSON（含医生端"患者标识"label）、`medications` JSON、`report` JSON、风险等级、评分 |
| `medications` | 药物知识 | 名称、JSON 别名、分类、适应症、药理、禁忌、监测等；`status` 软删除标记 |
| `interactions` | 已知相互作用 | 药物对（存药物名称而非 id）、严重度、机制、后果、建议 |
| `medication_contraindications` | 禁忌规则 | 药物、疾病关键词、严重程度条件。**机制已建、当前为空表（预期状态）** |
| `login_logs` | 登录审计 | 用户、成功状态、失败原因、IP、User-Agent |
| `admin_operation_logs` | 管理操作审计 | 管理员、操作类型、目标、脱敏摘要、IP |

SQL 脚本按编号顺序手工执行（同一份脚本适用于本地与云端；应用账号不承担 DDL 权限）：

- `01_schema.sql`：创建库和 6 张基础表（users/reports/medications/interactions/login_logs/admin_operation_logs）。
- `02_knowledge_seed.sql`：导入初始知识库（283 种药物、18 条相互作用）。
- `03_migrate_roles.sql`：用户表迁移为 patient/doctor/admin 角色体系。
- `04_migrate_knowledge_versioning.sql`：知识库版本治理（报告落库记录当时知识库版本）。
- `05_medication_contraindications.sql` / `05_migrate_drop_salt.sql`：建禁忌规则表、去除密码盐字段（BCrypt 自带盐）。
- `06_create_login_logs.sql`：登录日志表（与 01 中定义一致的历史迁移）。
- `07_common_otc_drugs.sql`：补录 18 种日常常用药品 + 28 条相互作用规则。

当前知识库实数：**301 种活跃药物（status=active）、46 条相互作用规则、0 条结构化禁忌规则**。历史脚本永不改写，变更一律新增编号脚本。

应用配置中的 `spring.sql.init.mode=never` 已明确关闭 Spring Boot SQL 自动初始化。

## 6. Redis 使用边界

Redis Key 使用 `medication-radar:` 前缀：

| 类型 | 示例 | TTL/策略 |
| --- | --- | --- |
| 药物详情缓存 | `medicationDetails::<id>` | 30 分钟 |
| 药物搜索缓存 | `medicationSearch::<query>:<limit>` | 5 分钟 |
| 分类统计缓存 | `knowledgeStats::SimpleKey[]` | 5 分钟 |
| 相互作用缓存 | `interactions::SimpleKey[]` | 30 分钟 |
| 限流计数 | `medication-radar:rate:<scope>:<ip>` | 1 分钟窗口 |
| JWT 注销 | `medication-radar:jwt:revoked:<jti>` | 到 Token 过期为止 |

缓存读写失败时：

- `@Cacheable` 读取失败回退数据库；
- 缓存写入失败不影响业务响应；
- 限流失败允许请求通过并记录告警；
- JWT 注销写入失败不会伪造成功状态，但已签发 Token 的主动失效能力会降级。

## 7. API 契约

前端目前依赖以下接口，Java 后端保持原字段命名和错误形状：

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| `GET` | `/api/health`、`/api/health/ready` | 公开 |
| `POST` | `/api/auth/register`、`/login` | 公开 |
| `POST` | `/api/auth/logout` | 登录 |
| `GET` | `/api/auth/me` | 登录 |
| `POST` | `/api/analyze` | 公开（游客不保存）；管理员 403；限流 6 次/分/IP |
| `GET` | `/api/reports`、`/api/reports/{id}` | 登录且仅本人 |
| `POST` | `/api/reports/{id}/favorite` | 登录且仅本人 |
| `DELETE` | `/api/reports/{id}` | 登录且仅本人 |
| `GET` | `/api/stats` | 登录且仅本人 |
| `GET` | `/api/medications`、`/search`、`/page`、`/stats`、`/interactions`、`/{id}` | 公开 |
| `POST/PUT/PATCH/DELETE` | `/api/medications/**` | 管理员（PATCH `/{id}/disable` 为填原因停用；DELETE 为物理删除） |

`POST /api/analyze` 的行为：

1. 药单为空、超过 15 项或存在空药名时返回 400。
2. 先匹配药物名称或别名（含剂型后缀剥离的精确匹配），再查询药物对相互作用。
3. 未收录药物进入 AI 外部检索流程：LLM 返回 `externalProfiles`，引擎逐个核对 `identified`；可识别的参与分析但强制标注推断属性（`grounded=false`、`evidenceLevel=低`、`external=true`）且永不计入风险分；不可识别的按"未收录、无法评估"处理，其 LLM 输出一律剔除。
4. LLM 调用失败的两种结局：清单内**有**本地可评估药物时，异常上抛为 502"报告生成失败"，不保存报告；**全部**为库外药物时，降级为确定性"未收录"拦截报告（不经 AI）。
5. 游客只获得报告；登录用户额外获得 `reportId` 并写入 `reports`。

## 8. 前端架构

- `api.js` 统一注入 `Authorization: Bearer <token>`，保存 `mradar_token` 和 `mradar_user`。
- 收到非登录/注册接口的 401 时清理本地会话并跳转登录页。
- `App.jsx` 按角色做路由守卫：管理员登录直落 `/knowledge`，访问 `/home` 自动重定向；`/dashboard` 仅患者；`/knowledge` 医生+管理员；后端权限校验是最终边界。
- `DrugAutocomplete` 调用药物搜索接口并提供防抖联想（键盘 ↑↓ 选择、Enter 上屏）。
- `AnalyzePage` 负责患者信息（含治疗方案、INR、血钾等临床字段）、长期/新增两组药物清单、提交状态和报告展示。
- `HistoryPage` 负责分页历史、风险筛选、药物搜索、收藏和删除；医生端按"患者标识"分组，文案为"分析记录"。
- `DashboardPage` 负责患者个人统计图表（纯 React + CSS 手绘，未使用图表库；`package.json` 中的 echarts 依赖未被引用）。
- `KnowledgePage` 负责药物列表、详情和相互作用展示；管理员可增删改停用，医生只读（无"停用"按钮）。
- `Report` 组件按登录角色渲染患者版/医生版：医生版决策式表述（`doctorNote`）、隐藏患者向区块（饮食建议、危险信号等），打印输出与登录角色一致。

Vite 开发代理配置为：

```text
/api -> http://localhost:8080
```

## 9. 配置和启动

Java 配置文件为 `backend-java/src/main/resources/application.yml`，运行时通过环境变量覆盖：

```text
DB_URL
DB_USERNAME
DB_PASSWORD
REDIS_HOST
REDIS_PORT
REDIS_PASSWORD
JWT_SECRET
DEEPSEEK_API_KEY
DEEPSEEK_BASE_URL
DEEPSEEK_MODEL
PORT
CORS_ALLOWED_ORIGINS
```

本地配置写入 `backend-java/.env`，该文件已被 Git 忽略。`scripts\start.ps1` 会：

1. 检查 Java、Node.js（缺失时可自动下载便携版到 runtime\）与 MySQL；
2. 首次运行时交互式生成 .env（数据库密码等），并自动安装前端依赖；
3. 启动 Java 8080 和 Vite 5173（使用仓库自带的预构建 jar，无需 Maven）；
4. 轮询 `/api/health/ready` 和前端首页（最多 90 秒），数据库未初始化时可一键建库；
5. 成功后打开浏览器并创建桌面快捷方式，失败则提示并展示日志。

DeepSeek 密钥为空时允许网站启动，但分析接口不可用（提示密钥未配置）。

## 11. 安全和数据边界

- 不把真实数据库密码、JWT 密钥或 DeepSeek 密钥提交到 Git；含真实密钥的本地启动脚本（`start-medication-radar.bat`）与运行日志（`logs/`）已在 `.gitignore` 排除。
- 不在审计日志中写密码、Token、患者详细资料、完整 Prompt 或完整报告。
- 报告接口始终带当前用户 ID 条件，防止跨用户读取。
- CORS 使用明确允许来源，不允许通配符凭据跨域。
- 患者疾病、用药和生命体征属于敏感健康信息；发送到 DeepSeek 前必须取得授权并确定脱敏、保留和删除规则。
- 医学事实只能来自本地知识库，AI 仅组织语言；AI 外部检索内容必须显著标注"推断"、永不计分，报告内提供人卫用药助手核实链接。
- 药物数据虽已备份并导入，但仍需要权威来源、审核责任人和版本治理，不能直接等同于临床结论。
